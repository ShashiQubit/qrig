# Testing pipeline: MQT Bench → Qiskit DAG → qrig (8 control equations) → MQT QCEC

This pipeline takes multi-controlled benchmark circuits from MQT Bench, runs them through
qrig's control-equation optimiser on Qiskit's `DAGCircuit`, records reduction
statistics, and uses MQT QCEC to check that the optimised circuit does the same thing
as the original.

```bash
pip install qiskit mqt.bench mqt.qcec        # tested with qiskit 2.5.2, mqt.bench 2.3.0, mqt.qcec 3.10.0
cd python
python3 benchmarks/mqt_quickstart.py grover 5   # your four-step script, with a real optimiser in step 2
python3 benchmarks/mqt_pipeline.py              # 51 circuits, writes mqt_results.md / .json
python3 benchmarks/mqt_pipeline.py --scale      # adds larger sizes (74 circuits, up to 128 qubits)
python3 benchmarks/mqt_pipeline.py --benchmarks grover qft --sizes 4 6 8
python3 examples/dag_rule_complementarity.py    # equation (e) as a DAG node-replacement rule
python3 -m pytest -q tests/test_dag.py          # 85 tests of the DAG pass
```

`mqt_pipeline.py` exits with a non-zero status if QCEC or the `Operator` check finds a
circuit that is **not** equivalent, or if a benchmark fails to run.

## Architecture

```
MQT Bench (algorithmic level)
   │  unroll composite gates (Q, Oracle, qft, …) until only standard/controlled gates remain
   ▼
Qiskit DAGCircuit ──topological order (measure/reset/barrier/swap as late as possible)──┐
   │  each node → multiply controlled one-qubit gates  C^{b1}_{w1}…C^{bk}_{wk}(U) on t     │
   │  (cx, ccx, mcx, cp, mcphase, crz, ch, c3sx, u, … any control state; angles as       │
   │   exact rationals × π; u(θ,φ,λ) = P(φ)·RY(θ)·P(λ) exactly; other gates → definition) │
   ▼                                                                                   │
verified core (C generated by Lean from Qrig/Core/Peephole.lean), rule statistics       │
   ▼                                                                                   │
new DAGCircuit (P·RY·P runs folded back into one u gate) ◄─── untouched operations ─────┘
   │
   ├─ metrics: gates, depth, ≥2-controlled gates, CX after Qiskit O3 with/without qrig
   └─ MQT QCEC: benchmark ≡ qrig output, and benchmark ≡ compiled circuit
      (+ Qiskit Operator comparison up to 7 qubits)
```

The pass can be used on its own:

```python
from qiskit.transpiler import PassManager
from qrig.dag import QrigControlEquations
pm = PassManager([QrigControlEquations(window=128)])
out = pm.run(qc)
print(pm.property_set["qrig_stats"].rules)
```

## Your two questions

### How does the optimiser handle the 8 equations: pattern matching or a symbolic rewriting matrix?

It uses pattern-matching rewrite rules. Matrices are only used in the Lean proofs, not
while optimising. Each DAG node becomes a multiply controlled one-qubit gate: a set of
`(wire, colour)` controls, a target wire, and a base gate. The core then goes through the
gates in DAG order. It tries to merge each new gate with an earlier one, moving it
backwards only past gates it provably commutes with (within a window of 128 gates). If no
merge is found, the gate stays where it was, so gates are never reordered for nothing.

| equation (Fig. 1) | how it is used | rule counter |
|---|---|---|
| (a) `C(f;g) = C(f);C(g)` | read right to left: two gates with the same controls and target fuse when `f;g` is again a base gate (`cp(a)cp(b) → cp(a+b)`, `T T → S`, `SX SX → X`) | `fuse` |
| (a)+(b) | when the fused gate is the identity, both disappear (`ccx ccx`, `mcx mcx`, `cp(a) cp(-a)`) | `cancel` |
| (b) `C(id) = id` | controlled identities are removed (e.g. `mcphase(2π)` in MQT's multipliers) | `idRem` |
| (d) colour change `x;C¹(f);x = C⁰(f)` | an `x` on wire `w` is pushed back through gates that only use `w` as a control, flipping those controls' colour, until it meets and cancels another `x` on `w` | `xconj` |
| (e) complementarity `C⁰(f);C¹(f) = id+f` | two gates that are identical except for the colour of one control merge into one gate without that control; repeating this collapses a whole multiplexer | `compl` |
| (f) `C⁰(f₁);C¹(f₂) = C¹(f₂);C⁰(f₁)` | gates with contradictory controls commute. This is extended to gates that share wires only as controls or as targets of diagonal gates (`p`, `rz`, `z`, `t`, …) | (enables moves) |
| (c), (g), (h) | structural equations about `+` and the swap σ. In the flat DAG view they are implicit in wire placement; (g) is how Qiskit defines `swap` | – |

**What is proved.** Lean proves every rule sound: `combine_sound` for (a), (b) and (e),
`commutes_sound` for (f) and diagonal commutation, and `xconj_sound` for (d). It also
proves the whole optimiser sound (`optimize_sound` in `QrigProofs/Peephole.lean`) for any
matrix interpretation of the base gates. For the concrete gate set with its complex
matrices, `peephole_sound` in `QrigProofs/PeepholeOps.lean` states that the optimised
gate list acts on every state vector **exactly** like the original. None of these
theorems depend on `sorry`, and they use only the standard axioms.

**What is not proved.** The Python conversion between Qiskit nodes and gate lists is not
proved. It is tested against Qiskit's `Operator` and checked by QCEC, and that check
found a real bug during development: `MCMTGate` (one control, several targets) had been
read as a single-target gate.

### Do you need help writing a sub-graph node replacement rule for Equation (e) inside the Qiskit DAG loop?

No. Equation (e) is already one of the verified rules and runs inside the DAG pass. For
reference, `examples/dag_rule_complementarity.py` contains a hand-written version as a
plain Qiskit DAG rule, built from `op_successors`, `substitute_node_with_dag` and
`remove_op_node`, and compares it with the verified pass:

```
== multiplexer k=3, RY(0.7): 8 gates
   hand-written DAG rule : 7 rewrites -> 1 gates, exact=True
   qrig (Lean-verified)  : compl=7 -> 1 gates, exact=True
== separated C0(H) / C1(H): 4 gates
   hand-written DAG rule : 0 rewrites -> 4 gates, exact=True
   qrig (Lean-verified)  : compl=1 -> 3 gates, exact=True
```

The hand-written rule only sees pairs that are adjacent in the DAG. The verified core
also finds pairs separated by gates they commute with (equation (f)), and its rewrites
are covered by the soundness proof.

## Results (`mqt_pipeline.py --scale`, full table in `mqt_results.md`)

This was one run on one machine. "CX" is the CNOT count after
`transpile(…, basis_gates=["cx","u"], optimization_level=3)` without qrig ("Qiskit O3")
and with qrig run first ("qrig+O3").

* **Correctness:** there were 74 circuits (20 benchmark families, 3 to 128 qubits).
  - QCEC found no non-equivalent result.
  - QCEC proved the qrig output equivalent to the benchmark for 72 of the 74. For
    `qft`/`qpeexact` at 32 qubits, QCEC timed out after 60 s; qrig made no rewrites there.
  - The Qiskit `Operator` comparison (exact, including global phase) agreed on all 37
    circuits with at most 7 qubits.
  - QCEC also checked the fully compiled qrig+O3 circuits. It proved 66, gave no answer
    for 2 (its ZX and simulation checkers disagreed), and timed out on 6.
* **CX count:** fewer CNOTs on 12 circuits, the same on 62, more on none. The total went
  from 37 058 to 32 565 (−12.1 %). Most of that total comes from the two largest Grover
  circuits, so read the per-circuit rows:

  | circuit | CX Qiskit O3 | CX qrig+O3 | rules that fired |
  |---|---|---|---|
  | grover n=4 | 52 | 38 (−27 %) | 4 × colour change (d) |
  | grover n=7 | 1 092 | 996 (−9 %) | 30 × (d) |
  | grover n=9 | 4 680 | 3 816 (−18 %) | 84 × (d) |
  | grover n=11 | 16 750 | 13 550 (−19 %) | 225 × (d) |
  | multiplier n=8 / 12 / 16 | 115 / 340 / 719 | 96 / 276 / 592 (−17 %) | 4 / 18 / 48 × identity removal (b) |
  | rg_qft_multiplier n=8 / 12 | 115 / 340 | 96 / 276 (−17 / −19 %) | (b) |
  | hrs_cumulative_multiplier n=5 / 9 | 130 / 500 | 128 / 494 | fusion + cancellation (a) |

  - In Grover, the oracle and diffuser surround multi-controlled gates with `x` layers.
    Equation (d) turns those into controls of colour 0 and cancels the `x` gates. Qiskit
    O3 does not remove them, and every remaining `x` next to an `mcx` costs extra CNOTs
    after synthesis. `grover n=6` is an exception: (d) fired 16 times but the CX count
    stayed at 456.
  - In the multipliers, MQT's circuits contain controlled phases of angle 2π (controlled
    identities). Qiskit keeps them and synthesises them.
* **No gain:** QFT/QPE, adders, GHZ, W-state, graph states, `qwalk` (only `x` gates are
  removed there), `ae`. These circuits contain no mergeable controlled structure.
* **Gate count and depth:** these can go *up* when a benchmark contains gates that the
  core cannot read: `MCMTGate`, `cswap`, `rzz`, `ecr` and the opaque blocks of
  `hrs_cumulative_multiplier`. Such gates are replaced by their Qiskit definitions, and
  the count is then of smaller gates (e.g. `hrs_cumulative_multiplier` n=5: 6 → 61
  gates). Compare CX counts instead. Depth grew on those 6 circuits only.
* **Speed:** the qrig pass took at most 0.06 s per circuit. The slow parts of the
  pipeline are QCEC on large compiled circuits and Qiskit's `Operator` beyond about 8
  qubits (which is why that check is limited to 7 qubits).

### Notes on QCEC results

* `equivalent_up_to_global_phase` often appears even when Qiskit's `Operator` says the
  matrices are exactly equal. For example, the unmodified benchmark checked against its
  O3-compiled version already reports it, and so does an exact multiplexer collapse. This
  comes from how QCEC represents some gates internally, so the pipeline accepts both
  `equivalent` and `equivalent_up_to_global_phase`. The pipeline counts only
  `not_equivalent` and `probably_not_equivalent` as failures. The exact `Operator` check
  (≤ 7 qubits) is stricter.
* `qcec.verify(..., timeout=…)` did not stop the construction checker in this version.
  The pipeline therefore runs each check in a child process with a hard limit
  (`--qcec-timeout`, 60 s in the run above; the script's default is 120 s).
* The script in the project brief used `bench.get_benchmark(benchmark_name=…,
  level="algorithmic")` and `qcec.EquivalenceStatus`. With mqt.bench 2.x / mqt.qcec 3.x
  these are `get_benchmark(name, BenchmarkLevel.ALG, n)` and
  `mqt.qcec.pyqcec.EquivalenceCriterion`, as used in `mqt_quickstart.py`.

## Suggested alternative approach

* Use the pass as a **pre-pass before Qiskit's own optimisation**. After Qiskit has
  lowered multi-controlled gates to CNOTs, the controlled structure that the equations
  work on is gone.
* Compare **CX count after compilation**, not raw `len(circuit.data)`. The raw count
  depends on how composite gates are unrolled.
* Keep QCEC on the qrig output as the acceptance test (it is fast). Treat QCEC on fully
  compiled large circuits as best effort, with a time limit.
